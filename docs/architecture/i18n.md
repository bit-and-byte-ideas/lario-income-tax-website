# Internationalization (i18n) Architecture

The Larios Income Tax website is fully bilingual, supporting English (en-US) and Spanish (es-MX)
using Angular's compile-time i18n system.

## Overview

- **Primary Locale**: English (en-US) — default when visiting root URL
- **Secondary Locale**: Spanish (es-MX) — accessible under `/es/` path
- **Architecture**: Compile-time translation with separate Angular builds per locale
- **Translation Format**: XLIFF 1.2 XML files

## URL Structure

```text
https://lariosincometax.com/          # English (en-US)
https://lariosincometax.com/es/       # Spanish (es-MX)
```

Each locale is a completely separate Angular application build, deployed to distinct directories in Azure Static Web Apps.

## Build Configuration

Angular's i18n is configured in `angular.json`:

```json
{
  "i18n": {
    "sourceLocale": "en-US",
    "locales": {
      "es-MX": {
        "translation": "src/locale/messages.es-MX.xlf",
        "baseHref": "/es/"
      }
    }
  }
}
```

**Build Output**:

```text
dist/larios-income-tax/browser/
├── en-US/          # English build (served from /)
│   ├── index.html
│   ├── main.js
│   └── ...
└── es-MX/          # Spanish build (served from /es/)
    ├── index.html
    ├── main.js
    └── ...
```

## Translation Files

### Location

- **Source messages**: `src/locale/messages.xlf` (English, auto-generated)
- **Spanish translations**: `src/locale/messages.es-MX.xlf` (manually maintained)

### Format

XLIFF 1.2 XML with translation units:

```xml
<trans-unit id="abc123" datatype="html">
  <source>English text</source>
  <target>Texto en español</target>
  <context-group purpose="location">
    <context context-type="sourcefile">src/app/component.html</context>
    <context context-type="linenumber">5</context>
  </context-group>
  <note priority="1" from="description">Context hint for translator</note>
</trans-unit>
```

## Marking Content for Translation

### In Templates

Use the `i18n` attribute on elements:

```html
<!-- Simple text -->
<h1 i18n="Hero|Main headline">Welcome to Larios Income Tax</h1>

<!-- Element with attributes -->
<img src="logo.avif" i18n-alt="Logo|Alt text for logo" alt="Larios logo" />

<!-- Element with variables (interpolation) -->
<p i18n="Contact|Phone number">Call us at {{ phoneNumber }}</p>
```

**Format**: `i18n="Context|Description"` where:

- **Context**: Category for organizing translations (e.g., "Hero", "Services", "Contact")
- **Description**: Hint for translators explaining the text's purpose

### In TypeScript

Use `$localize` for dynamic strings:

```typescript
import { $localize } from '@angular/localize/init';

// In services, components, etc.
const greeting = $localize`:Hero|Greeting:Welcome to Larios`;

const title = $localize`:Services|Tax Preparation title:Tax Preparation`;

// With variables (interpolation must happen after)
const message = $localize`:Contact|Dynamic message:You reached us at` + ` ${timestamp}`;
```

**Format**: `` $localize`Context|Description:English text` ``

### Service Catalog

All service titles and descriptions in `src/app/shared/constants/services.constants.ts` use `$localize`:

```typescript
{
  id: 'tax-preparation',
  title: $localize`:Services|Tax Preparation service title:Tax Preparation`,
  description: $localize`:Services|Tax Preparation full description:Our professional tax preparation services...`,
  // ... other fields
}
```

## Translation Workflow

### 1. Mark Text for Translation

Add `i18n` attributes or `$localize` calls to your code.

### 2. Extract Strings

```bash
npm run extract-i18n
```

This command:

- Scans all templates and TypeScript files
- Generates/updates `src/locale/messages.xlf` with new translation units
- Existing translations in `messages.es-MX.xlf` are preserved

### 3. Add Spanish Translations

Edit `src/locale/messages.es-MX.xlf` and add `<target>` elements for new units:

```xml
<!-- New unit (no target yet) -->
<trans-unit id="new-id" datatype="html">
  <source>New English text</source>
  <!-- Add this line: -->
  <target>Nuevo texto en español</target>
  <context-group purpose="location">
    <context context-type="sourcefile">src/app/component.html</context>
  </context-group>
</trans-unit>
```

### 4. Build and Test

```bash
# Build both locales
npm run build:i18n

# Test in development
npm run start:en   # English
npm run start:es   # Spanish
```

### 5. Commit Changes

Always commit source code changes and XLIFF files together:

```bash
git add src/app/...
git add src/locale/messages.xlf
git add src/locale/messages.es-MX.xlf
git commit -m "feat: add new feature with translations"
```

## Locale-Aware Features

### Language Switcher

The header includes a language switcher component that navigates between locales:

- Click the 🇺🇸 US flag to go to English (`/`)
- Click the 🇲🇽 Mexico flag to go to Spanish (`/es/`)

The active locale is visually highlighted.

### Contact Page Behavior

The contact page automatically displays the correct office location based on the current locale:

- **English locale** (`/contact`): Shows San Diego, CA office
- **Spanish locale** (`/es/contacto`): Shows Tijuana, B.C. office

No special URL parameters are needed — the locale determines the display.

## SEO and hreflang

All pages include proper `<link rel="alternate" hreflang="...">` tags in the document head for search engine optimization:

```html
<link rel="alternate" hreflang="en-US" href="https://lariosincometax.com/" />
<link rel="alternate" hreflang="es-MX" href="https://lariosincometax.com/es/" />
<link rel="alternate" hreflang="x-default" href="https://lariosincometax.com/" />
```

These are automatically injected by the `SeoService` and help search engines understand alternate language versions.

## Azure Static Web Apps Configuration

The `staticwebapp.config.json` handles locale-based routing:

```json
{
  "routes": [
    {
      "route": "/es/*",
      "serve": "/browser/es-MX/index.html",
      "statusCode": 200
    },
    {
      "route": "/*",
      "serve": "/browser/en-US/index.html",
      "statusCode": 200
    }
  ]
}
```

This ensures:

- Requests to `/` serve the English build
- Requests to `/es/*` serve the Spanish build
- SPA fallback routes work within each locale

## Best Practices

### Do's

- Always wrap new text in `i18n` or `$localize` markers before extraction
- Keep context and description hints clear and concise
- Run `npm run extract-i18n` regularly to catch new strings
- Test both locales before committing (`npm run start:en` and `npm run start:es`)
- Commit source and translation changes together

### Don'ts

- Don't manually edit `messages.xlf` (it's auto-generated; your edits will be lost)
- Don't forget to add Spanish translations to `messages.es-MX.xlf` before building
- Don't use interpolation in the `$localize` string itself — interpolate after localization:

  ```typescript
  // WRONG:
  const msg = $localize`:Context|Desc:Value is ${value}`;

  // RIGHT:
  const msg = $localize`:Context|Desc:Value is` + ` ${value}`;
  ```
